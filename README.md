# 轻记 · 个人记账系统

一个面向移动端的个人记账应用：随手记一笔，自动汇总当月收支、分类占比和预算进度。
包含**邮箱注册、邮箱 + 密码登录、忘记密码**、**记账 / 分类 / 预算 / 统计**完整功能，以及一个**管理员后台**。

---

## 一、技术选型

| 层 | 技术 | 说明 |
|---|---|---|
| 前端 | Vue 3 + Vite + Vant 4 | Vant 是移动端组件库，页面按手机尺寸设计；Pinia 管状态，Vue Router 管路由，Axios 管请求 |
| 后端 | Node.js + Express | 无原生依赖，`npm install` 后即可运行 |
| 数据 | JSON 文件（原子写盘） | 数据量小，省去装数据库；金额统一以「分」存储避免浮点误差 |
| 鉴权 | scrypt 密码摘要 + HMAC 签名 Token；邮箱验证码用于注册和找回密码 | 密码不落明文；Token 无状态，改密码后旧 Token 立即失效；验证码 10 分钟有效并限流防刷 |

> 金额为什么用「分」：`0.1 + 0.2 = 0.30000000000000004` 这类浮点误差在记账里是硬伤，
> 所以后端所有金额都是整数分，只在返回给前端展示时才除以 100。

## 二、快速开始

需要 **Node.js ≥ 18**（用 `node -v` 检查）。

### 1. 启动后端

```bash
cd server
npm install
npm start          # 默认 http://localhost:3000
```

首次启动会自动创建数据库文件、系统默认分类和管理员账号，无需手动初始化。
管理员密码不会写死在代码里：在 `server/.env` 设置 `ADMIN_PASSWORD`；留空时首次启动会随机生成并写回该文件。

### 2. 启动前端

**另开一个终端：**

```bash
cd web
npm install
npm run dev        # 默认 http://localhost:5173
```

浏览器打开 `http://localhost:5173`，建议按 `F12` 切换到**手机模拟视图**（如 iPhone 尺寸）体验。
前端开发服务器已把 `/api` 代理到后端 3000 端口，不存在跨域问题。

### 4. 邮箱注册 / 登录 / 找回密码

前端登录流程：

1. **注册**：填写邮箱 → 获取验证码 → 输入验证码、昵称和密码 → 注册成功；
2. **登录**：回到登录页，用邮箱 + 刚刚设置的密码登录；
3. **忘记密码**：输入注册邮箱 → 获取验证码 → 设置新密码 → 用新密码登录。

注册验证码用于证明邮箱归属，防止别人用你的邮箱抢注；找回密码验证码只发给已注册邮箱。

**不配置 SMTP 也能开发**：开发环境会把验证码打印到后端控制台，并自动填入页面，接口流程和真实发信完全一致。

要真实收到邮件，复制配置模板：

```bash
cd server
cp .env.example .env      # Windows 可用 copy .env.example .env
```

然后编辑 `server/.env`：

| 变量 | 说明 |
|---|---|
| `SMTP_HOST` | QQ：`smtp.qq.com`；163：`smtp.163.com`；Gmail：`smtp.gmail.com` |
| `SMTP_PORT` | 一般填 `465` |
| `SMTP_SECURE` | 端口 465 填 `true` |
| `SMTP_USER` | 你的邮箱地址 |
| `SMTP_PASS` | **SMTP 授权码**（不是邮箱登录密码） |
| `MAIL_FROM` | 发件人，通常与 `SMTP_USER` 相同 |
| `EMAIL_DEV_MODE` | `auto`：配好就真发；`true`：强制控制台；`false`：强制真发 |

授权码在邮箱网页版的设置里开启 SMTP 服务后生成：

- **QQ 邮箱**：设置 → 账号 → 开启「POP3/IMAP/SMTP/Exchange/CardDAV/CalDAV 服务」→ 按提示验证后获取授权码。
- **163 邮箱**：设置 → POP3/SMTP/IMAP → 开启 SMTP 服务 → 设置客户端授权密码。
- **Gmail**：Google 账号 → 安全性 → 两步验证 → 应用专用密码（国内网络可能连不上 `smtp.gmail.com`）。

`server/.env` 已在 `.gitignore` 中，不会被提交。配置后重启后端即可真实发信；收不到时先看垃圾箱和后端日志。

**账号初始密码**：

| 变量 | 说明 |
|---|---|
| `ADMIN_PASSWORD` | 首次创建管理员时使用；留空则随机生成并写入 `server/.env` |
| `DEMO_PASSWORD` | 演示账号统一密码，默认 `Demo@2026!` |

如果数据库里已经有账号，修改这两个变量不会自动生效；停止后端后执行 `npm run set-passwords` 再重启即可。

如果要求「所有用户必须真实收到邮件才能注册 / 重置密码」，把 `.env` 里的 `EMAIL_DEV_MODE` 设为 `false`：
这样未配置 SMTP 或配置错误时，发送接口会直接报错，不会降级成控制台验证码。

### 5. AI 辅助记账（本地规则 + 可选免费云模型 + 本地 OCR）

首页「一句话记多笔」或「记一笔」右上角 AI 打开智能记账：

- **文字记账**：输入「昨天午饭 35，打车 22」→ 解析成两笔可编辑草稿 → 确认保存
- **智能分类**：按关键词和用户自己的分类列表推荐分类，不确定的会标「请核对」
- **问一问**：基于月度聚合统计回答问题（花了多少 / 哪类最多 / 预算 / 环比…）
- **拍照识别**：**本地 OCR** 读取小票，提取金额、日期、商户和分类，可再修改

它有三种运行方式，默认不需要任何账号、密钥或费用：

| 模式 | 怎么开启 | 能力 | 数据 |
|---|---|---|---|
| 本地规则（默认） | 不用配置 | 覆盖常见说法和固定问答 | 完全本机 |
| 免费云模型 | 在 `server/.env` 填 `AI_API_KEY` 等 | 自然语言理解更好、可自由问答 | 只发输入 + 分类名 + 月度聚合统计 |
| 本地 OCR | 装依赖即用 | 真实识别小票（中文 + 英文） | 图片不出本机 |

**接免费云模型**（OpenAI 兼容协议，任选其一）：

```dotenv
# 方式一：OpenRouter（有免费模型，注意每日额度）
AI_PROVIDER=openrouter
AI_BASE_URL=https://openrouter.ai/api/v1
AI_MODEL=从 https://openrouter.ai/models?max_price=0 选一个
AI_API_KEY=你的 key

# 方式二：Google Gemini 免费额度（国内网络可能连不上）
AI_PROVIDER=gemini
AI_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai
AI_MODEL=gemini-2.5-flash
AI_API_KEY=你的 key

# 方式三：智谱 GLM-4-Flash（国内可直连，有免费额度，以官网为准）
AI_PROVIDER=openai
AI_BASE_URL=https://open.bigmodel.cn/api/paas/v4
AI_MODEL=glm-4-flash
AI_API_KEY=你的 key
```

改完重启后端生效。界面顶部会显示「本地规则」或「云端 · 模型名」。

**失败自动降级**：云模型超时、限流、额度用完或密钥失效时，后端会冷却 60 秒并自动
使用本地规则，不会让记账流程卡住；界面会提示本次是哪种模式。

**免费额度下长期使用（1–5 人、后端在服务器上）**：

服务器通常没有 GPU，不建议在服务器上跑本地大模型；推荐「免费云模型 + 本地规则 + 本地 OCR」：

```dotenv
AI_CHAT_MODE=auto        # 固定问题本地回答，只有规则答不了才调云端
AI_RECEIPT_MODE=auto     # 本地 OCR 已提取到金额就不调云端
AI_DAILY_CLOUD_LIMIT=200 # 全局每日上限（所有用户合计），建议设为供应商日额度的 80%
```

- 默认的 `auto` 模式会先把固定问答（花了多少 / 哪类最多 / 预算 / 环比）和能识别的小票
  在本地处理掉，**大部分请求不消耗云端额度**；
- `AI_DAILY_CLOUD_LIMIT` 用满后自动回退本地规则，接口不会报错；
- 国内服务器优先选可直连的 OpenAI 兼容免费服务（如智谱 GLM-4-Flash、硅基流动的部分模型），
  额度以各家官网当前说明为准；OpenRouter / Gemini 免费层在国内网络可能连不上；
- 免费额度只适合低频的小规模使用；公开多用户或要求稳定体验时，应改为付费 API 或自建模型。

**隐私边界**：
- 文字解析只发送当前这段输入和你的分类名称，不发送历史账目；
- 问答只发送月度聚合统计（收入/支出/分类占比/预算），不发送逐笔备注；
- 小票只把本地 OCR 出来的文字发给云模型（若已配置），**不上传原图**；
- API Key 只存在 `server/.env`，不会下发到前端。

**小票识别说明**：使用 `tesseract.js` 在本机识别，首次识别会下载中文语言包
（约 20–30MB，缓存到 `server/data/tessdata/`，之后离线可用）。下载源默认是
projectnaptha 静态镜像，避免 tesseract.js 自带的 jsdelivr 在国内网络被重置；
如果仍然下载失败，可以完全离线：把解压后的 `chi_sim.traineddata`、`eng.traineddata`
直接放进 `server/data/tessdata/`；或者把 `chi_sim.traineddata.gz`、`eng.traineddata.gz`
放在任意目录，再把 `OCR_LANG_PATH` 指向该目录（也支持其他镜像 URL）。
对清晰、正对的小票效果较好；褶皱、反光或手写小票会识别不准，所以结果一律作为可编辑草稿。

AI 生成的内容永远只是**草稿**：必须在页面上核对金额、分类、日期和备注，
点「确认保存」后才会写入账本。免费模型和 OCR 都可能出错，人工确认是最后一道防线。

### 6. 数据文件在哪

所有数据都在一个文件里，没有数据库：

| 文件 | 内容 |
|---|---|
| `server/data/db.json` | **主数据文件**：用户、分类、账单、预算（可直接用记事本 / VS Code 打开看） |
| `server/data/secret.key` | 会话签名密钥，自动生成，请勿泄露或提交到仓库 |

`server/data/` 已在 `.gitignore` 里。想备份全部数据，复制 `db.json` 即可。

### 7. 单端口部署（可选）

先构建前端，后端会自动托管构建产物，之后只跑一个服务即可：

```bash
cd web && npm run build
cd ../server && npm start
```

然后直接访问 `http://localhost:3000`。

## 五、设计要点

**业务规则**

- 金额必须大于 0 且最多两位小数，前后端双重校验；后端以「分」存储
- 分类必须与记录类型（收入/支出）一致，否则拒绝保存
- 已被记录引用的分类不允许删除，接口会返回「该分类下还有 N 条记录」的提示
- 预算为「未设置」和「预算为 0」是两种状态，分别返回 `null` 和 `0`
- 统计按记录**发生日期**归属月份（不是创建时间）

**数据隔离**

所有涉及记录 / 分类 / 预算的接口，都会用 `userId` 过滤当前登录用户的数据。
即使手动构造请求参数传别人的 `categoryId`，也会因为归属校验被拒绝。

**交互体验**

- 首页/账单/统计页都支持滑动切换月份，切换即刷新
- 记账页自动聚焦金额输入框并唤起数字键盘，常用备注一键填入
- 删除等破坏性操作均有二次确认；所有操作都有 Toast 反馈
- 空状态有引导文案和按钮，不会出现一片空白的页面

## 八、安全说明

本项目用于学习与课程演示，生产环境部署前建议补充：

- 通过 `APP_SECRET` 环境变量注入会话密钥（不要用自动生成的 `data/secret.key`）
- 开启 HTTPS，并给登录接口加更严格的风控
- 将 JSON 文件存储替换为正式数据库，并做定期备份

邮箱登录相关：

- 验证码只存在内存中（10 分钟有效、一次性、加盐摘要），多实例部署需要换成 Redis 等共享存储
- 同一邮箱 60 秒内只能发一次、每小时最多 5 次；同一 IP 每小时最多 20 次；单条验证码最多试错 5 次
- `server/.env` 里的 `SMTP_PASS` 是邮箱授权码，务必不要提交到仓库
- 注册和找回密码都必须验证邮箱验证码；登录只需要邮箱 + 密码
- 演示账号使用 `@qingji.local` 内部邮箱，不接收真实邮件；正式用户请使用真实邮箱
- 清理用户前先停止后端；`npm run prune-users` 会自动备份 `db.json`，管理员和演示账号不会被删除

AI 辅助记账相关：

- 默认 `AI_PROVIDER=mock`：解析、问答、OCR 都在本机完成，不联网、不上传账目
- 配置免费云模型后，只发送当前输入、分类名称和月度聚合统计，不发送逐笔备注，也不上传小票原图
- 云端超时/限流/额度用尽会冷却 60 秒并自动回退本地规则，记账流程不中断
- AI 结果只是草稿，必须用户确认后才写入；金额、日期、分类都会再校验一次
- 问答只读取本月聚合统计（收入、支出、分类占比、预算），不读取逐笔备注
- AI 接口按用户限流：解析 30 次/小时、问答 40 次/小时、小票 10 次/小时
- 免费部署默认 `AI_CHAT_MODE=auto` / `AI_RECEIPT_MODE=auto`，固定问答和本地可识别的小票不消耗云端额度
- `AI_DAILY_CLOUD_LIMIT` 是全局每日云端调用上限（所有用户合计），计数在进程内存里，重启会清零；
  多实例部署需要换成 Redis 等共享计数
- 没有 GPU 的服务器不建议自建大模型；本地 7B/8B 模型更适合个人电脑，服务器上用免费云模型更现实
- `AI_API_KEY` 只放在 `server/.env`（已 gitignore），绝不下发前端
- 免费模型通常有每日次数限制，且输出质量不稳定；OCR 对模糊照片也会出错，务必人工核对
